## Authentication Methods

The API authenticates requests with an API token sent as `X-Aegister-Token`. To create one, see [Token](/api-reference/token).

### 1. Header-Based Authentication

Include the `X-Aegister-Token` in the request headers. This is the supported method: it keeps the token out of the URL and out of server logs.

**Example Request:**

```http
GET /api/v1/organizations HTTP/1.1
Host: app.aegister.com
X-Aegister-Token: your_token_here
```

**Curl Example:**

```bash
curl -H "X-Aegister-Token: $TOKEN" https://app.aegister.com/api/v1/organizations
```

**Example Response** (fields trimmed):

```json
{
  "error": 0,
  "messages": [],
  "total": 1,
  "data": [
    { "id": 123, "name": "Example Organization" }
  ]
}
```

A missing or invalid token returns HTTP `401`:

```json
{ "error": 1, "messages": [2168] }
```

### 2. Query Parameter Authentication (deprecated)

<Warning>
Passing the token in the URL, as an `X-Aegister-Token` query parameter, is deprecated and will be removed. A token in the URL ends up in proxy and server logs and in browser history. Send the `X-Aegister-Token` header instead, as shown above.
</Warning>

## Rate limits

Every API call counts towards a limit per user account: 300 calls a minute, shared by all your
tokens and your console session. Some costly calls have their own limit, also per user:

| Call | Limit |
|---|---|
| AI task fill (`POST …/tasks/{tid}/prefill`) | 20 an hour |
| Cloud Defender web app check (precheck) | 30 a minute |
| Reports and PDF exports | 10 a minute |

Aegister can also set a daily cap on a token, or on one endpoint for your account. Over a limit the
call answers HTTP `429` with a `Retry-After` header, in seconds:

```json
{ "error": 1, "messages": [4290] }
```

Wait that many seconds and try again. After a daily cap, `Retry-After` counts to midnight UTC, and the
refused call is not counted.

## Request size

A request body over 32 MB is refused with HTTP `413`:

```json
{ "error": 1, "messages": ["Payload too large"], "data": {} }
```

The server answers without reading the rest of the upload, so some clients report a dropped
connection or a `502` instead. Send a large log file raw (`application/octet-stream`, up to 100 MB):
see “Create log analysis”.
